Документация для Даниила.

В проекте пытался использовать слоеную архитектуру.

В папке cmd лежит точка входа в приложение.

В папке internal лежит основной код.

Далее по папке internal:
- api - маршрутизация запросов
- config - конфиг, формируется из файла .env
- db - подключение к базе данных
- middleware - промежуточный слой между запросом и его обработкой (выполняется до основной логики)
- model - модели сущностей (некоторые сгенерированы protobuf)
- repository - слой запросов к базе данных
- service - основная логика

Движение запроса: middleware -> api -> service -> repository -> service

Для операций с пикселями использутся вебсокеты - [api](internal/api/websocket.go), [service](internal/service/ws/wsService.go)

Все данные передаются по протоколу http - просто десериализуются из байтов в объекты и наоборот при помощи технологии protobuffers.

[файлы-описания для последующей генерации protobuf моделей](proto/)

ORM не используется - используется ручное создание объектов

После oauth используются jwt-токены, хранятся в куках.

Файл .env должен лежать в корне проекта (на одном уровне с докер файлом).

Пример .env файла

```
GITHUB_CLIENT_ID="id"
GITHUB_CLIENT_SECRET="secret"
GITHUB_REDIRECT_URL="url"
JWT_SECRET="secret"
PIXEL_FIELD_WIDTH=500
PIXEL_FIELD_HEIGHT=500
```

Если нечего делать - вот задачка: прикрутить сжатие gzip, чтобы ускорить работу. Это нужно будет сделать на уровне бекенда с помощью библиотек и на уровне nginx.
